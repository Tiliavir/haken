# ADR-20261104: *Today* without a daily reset

Status: Accepted

## Decision

- *Today* has two parts, in this order:
  1. Open tasks **due today or overdue**, oldest due date first.
  2. Tasks the user **put on Today**, most recently added first.
  Below them, collapsed: tasks completed today that were due or on Today.
- A task put on Today **stays there** until the user takes it off. There is no reset at midnight. A task that is due and on Today shows once, in the first part.
- Stored as `X-HAKEN-MYDAY:<YYYYMMDD>`, the day it was put on Today (used for the order). Adding it again keeps the first day. The value is validated like every interpreted property.
- Put on Today: *Add to Today* in the task screen, or drag a task row onto *Today* in the sidebar. Take off: *Remove from Today*. A task added inside *Today* goes on Today without a due date.
- Overdue dates are red (`--danger`, at least 4.5:1 in both schemes) in every list; a task due today shows an exclamation mark; a task on Today shows a sun marker.
- Completing a repeating task on Today advances it and leaves it on Today.

## Why

- This is how the user works: today's must-dos at the top, the chosen tasks below, and the choice is not lost overnight.
- An `X-` property is the only option (no standard exists); other clients ignore and preserve it. A date instead of a flag gives a stable order and the history of the choice.
- Red is reserved for one meaning, "overdue", so it stays a signal; the accent colour stays the only colour for everything else.
